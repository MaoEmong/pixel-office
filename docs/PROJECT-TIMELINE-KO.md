# 프로젝트 진행 상황과 기록

사무실 위에는 현재 목표와 작업 단계, 사용자 확인이 필요한 요청을 표시합니다. 내부 질문은 상사의 답변 대기로 구분합니다. 요청 전달을 확인하기 전에는 작업 중이라고 단정하지 않습니다.

AI가 다른 담당자의 결과를 기다리면 사무실 위에 대기 상대를 표시합니다. 항목을 누르면 해당 AI의 상태를 확인할 수 있습니다. 조용하다는 이유만으로 작업이 멈췄다고 판단하지 않습니다.

오른쪽 **진행·기록**에서 사용자 요청, 부장의 답변, 팀장·팀원의 참여, 파일 확인·수정, 실행, 질문·허가, 완료 보고를 시간순으로 확인할 수 있습니다. 최근 기록부터 표시하며 이전 기록을 추가로 불러올 수 있습니다. 명령 원문은 별도로 펼쳐 봅니다. AI의 내부 생각을 추측해서 기록하지 않습니다. 이전 버전에서 수집하지 않은 행동을 만들어 채우지 않습니다.

## 파일 저장

첫 작업을 보내기 전, 그리고 작업의 완료 보고를 받으면 프로젝트 파일을 별도의 로컬 Git 기록에 저장합니다. **현재 파일 저장**으로 직접 저장할 수도 있습니다. Git이 설치되어 있어야 하며 저장에 실패하면 문제 기록에 이유를 남깁니다.

같은 폴더에서 여러 AI가 작업하므로 저장 지점은 담당자 한 명의 변경만이 아니라 그때의 프로젝트 전체 파일 상태입니다. 아직 다른 AI가 작업 중인 변경도 포함할 수 있습니다. 저장이 진행되는 동안 파일이 달라져 완전한 상태를 확인할 수 없으면 저장 실패로 표시합니다.

원래 프로젝트의 Git 기록과 준비 중인 커밋은 변경하지 않습니다. 원격 저장소에 올리지 않습니다. 기록은 앱 데이터 폴더의 `project-history.db`와 `checkpoints`에 보관합니다. 앱 데이터 폴더를 지우면 이 기록도 사라집니다.

## 파일 되돌리기

1. 파일 저장 기록을 펼쳐 **이 시점의 파일로 되돌리기**를 누릅니다.
2. 복원·삭제할 파일과 복구 범위를 확인합니다. 확인 중 파일이 달라지면 다시 확인해야 합니다.
3. 확인하면 같은 폴더나 겹치는 폴더의 AI를 모두 멈춥니다.
4. 현재 파일을 먼저 안전 보관하고, 선택한 시점의 파일을 복원합니다. 이 안전 보관 지점도 타임라인에서 선택할 수 있습니다.
5. 부장을 재고용하고 현재 파일을 기준으로 새 지시를 보냅니다. 과거 시점 이후의 AI 대화를 그대로 이어 실행하지 않습니다.

복구 대상은 저장한 파일입니다. 대화와 타임라인, 외부 데이터베이스·웹사이트·배포 상태는 과거로 돌아가지 않습니다. `.gitignore`로 제외된 미추적 파일, 알려진 비밀값 파일 이름과 인증서, 생성 폴더, 연결 파일, 앱 데이터 등은 저장·복구에서 제외합니다. 저장된 이력이 없는 새 파일은 자동 삭제하지 않습니다. 편집기나 별도로 실행한 프로그램의 파일 변경은 복구 전에 직접 멈춰야 합니다.

이 기능은 Windows 0.2.0에 포함되어 있습니다. 파일 저장·되돌리기는 사용자 PC에서 동작하며 원격 저장소로 전송하지 않습니다.
