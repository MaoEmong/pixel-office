# 픽셀 오피스 0.2.1 — Windows 사용 안내

Windows 10·11의 64비트 PC를 위한 시험판입니다. 중요한 프로젝트보다 복사본이나 연습용 폴더로 먼저 사용해 보세요.

## 실행과 준비

1. ZIP **전체**를 쓰기 가능한 새 폴더에 풉니다. ZIP 안에서 바로 실행하거나 실행 파일만 따로 옮기지 마세요.
2. `pixel_office.exe`를 실행합니다. `data`, `dev`, `runtime` 폴더와 DLL 파일을 함께 두세요.
3. 사용할 [Claude Code](https://code.claude.com/docs/en/setup), [Codex CLI](https://developers.openai.com/codex/cli/), [Antigravity CLI](https://antigravity.google/docs/cli/)를 별도로 설치하고 로그인합니다. AI 계정·요금·사용 한도는 각 서비스의 조건을 따릅니다.
4. 첫 화면의 **준비 상태 확인**에서 연결을 확인합니다. **부서 만들기**에서 프로젝트 폴더, 부장 AI와 팀에서 사용할 AI를 고릅니다.
5. 작은 읽기 작업부터 지시합니다. 예: “폴더의 구조와 실행 방법을 설명해줘. 아직 파일은 바꾸지 마.”

Node.js와 앱 실행 구성품은 ZIP에 포함됩니다. Flutter·Visual Studio·npm은 앱 사용에 필요하지 않습니다. **파일 저장 지점과 되돌리기에는 별도의 Git 설치가 필요합니다.** Git이 없으면 해당 기능의 실패 이유를 안내합니다.

서명 없는 시험판이므로 Windows에서 제작자를 확인할 수 없다는 안내가 나올 수 있습니다. 공식 배포 저장소와 ZIP의 SHA256 값을 확인하세요. 다른 PC의 최초 설치·로그인은 아직 검증하지 않았습니다.

## 화면과 작업

- 왼쪽 목록의 각 **부서**는 선택한 작업 폴더입니다. 부서 안에 부장·팀장·팀원이 배치됩니다.
- 아래 입력칸으로 부장에게 목표와 완료 기준을 전달합니다. 작업 중에도 질문하거나 지시를 바꿀 수 있습니다.
- **부장과 대화 · 회의 보기**에서 결정과 보고를 확인합니다. **내 책상**에는 사용자가 답변하거나 허가할 항목이 모입니다. AI끼리의 질문은 상사가 처리합니다.
- 오른쪽 **진행·기록**에서 요청별 기록과 완료 결과를 봅니다. 완료 카드의 결과 화면은 등록한 웹 미리보기를 열며, 완료 당시 사진을 저장하는 기능은 아닙니다.
- 오른쪽 **파일·문서**에서 프로젝트 폴더와 UTF-8 `.md`, `.markdown`, `.txt` 파일을 읽고 편집합니다. 문서는 2MB까지 지원합니다. AI가 동시에 수정하면 최신 내용을 비교한 뒤 다시 열어야 하며, 자동 덮어쓰기는 하지 않습니다.
- **파일 목록**으로 다른 문서를 고르거나 **문서 넓게 보기**로 확대할 수 있습니다. 앱을 완전히 닫기 전에 편집 중인 글을 저장하세요.

## 파일 저장과 되돌리기

Git이 설치되어 있으면 첫 지시 전과 완료 보고 후에 파일 저장을 시도합니다. **현재 파일 저장**으로 직접 저장할 수도 있습니다. 원래 프로젝트의 Git 준비 영역·커밋·원격 저장소는 바꾸지 않습니다.

되돌릴 때는 저장 기록을 펼쳐 **이 시점의 파일로 되돌리기**를 누르고 복원·삭제 범위를 확인합니다. 확인 후에는 겹치는 폴더의 AI를 멈추고 현재 파일을 먼저 보관한 뒤 복원합니다. 대화·타임라인·외부 데이터베이스·온라인 전송까지 과거로 되돌리지는 않습니다. `.gitignore` 제외 파일과 알려진 비밀값 파일 등은 저장 대상에서 빠집니다.

자세한 범위는 [프로젝트 기록 안내](https://github.com/MaoEmong/pixel-office/blob/main/docs/PROJECT-TIMELINE-KO.md)를 참고하세요. 같은 폴더의 여러 AI가 수정한 상태가 한 저장 지점에 함께 담길 수 있습니다.

## 대기·한도·연결 복구

답변·허가 대기와 입력 접수 실패는 **확인 대기**에 표시합니다. **확인하기**를 누르면 해당 항목으로 이동합니다. 짧은 하단 알림은 사라져도 해결 전에는 화면의 대기 안내가 유지됩니다.

사용 한도가 소진되면 해당 부서의 실행을 멈춥니다. 앱에서 허용한 다른 구독 AI의 연결과 남은 한도가 확인되면 교체 여부를 묻습니다. **교체하고 계속**을 눌러야 바뀌며, 후보가 없거나 교체하지 않으면 중지 상태를 유지합니다. 사용량이 확인되지 않았다는 이유만으로 무제한 또는 소진으로 판단하지 않습니다.

연결 복구가 오래 멈춘 AI는 **AI 상세 → 강제 퇴근**에서 영향 범위를 확인한 뒤 종료할 수 있습니다. 팀장을 종료하면 하위 팀원도 종료합니다. 이미 바뀐 파일은 남습니다. 후임을 불러 미완료 업무를 이어가려면 부장에게 요청하세요.

사용 한도 때문에 이미 중지된 부서는 실행이 종료된 상태이므로 퇴근 대신 **AI 선택·다시 확인**에서 재개하거나 교체합니다.

Docker 때문에 멈췄다는 보고에는 실행 대기 카드가 나옵니다. **Docker 실행**은 설치된 Docker Desktop에 실행을 요청하고, **다시 확인**으로 준비 여부를 검사합니다. 준비가 확인된 뒤 **작업 이어가기**를 선택하세요. Docker 설치·재설치·데이터 초기화는 자동으로 하지 않습니다.

로그인 문제는 **환경 점검 · CLI 로그인**이나 해당 AI의 **터미널 → 로그인**에서 해결합니다. 처음 접근하는 프로젝트 폴더의 허가는 경로를 읽고 판단하세요. Antigravity 사용량의 내부 모델 그룹은 별도 Claude Code·Codex 계정의 사용량과 다릅니다.

## 키와 권한

상단 메뉴의 **키 저장소**에 이름과 값을 저장할 수 있습니다. Windows 계정에 연결해 암호화하며, 해당 프로젝트의 AI가 조회할 수 있습니다. AI에게 넘긴 값은 AI 서비스와 CLI 기록에 포함될 수 있습니다. 앱의 가림 처리가 모든 노출을 막거나 외부 기록을 지우지는 않습니다.

기본은 실행 허가를 묻는 방식입니다. **모든 권한 허용**은 경고와 이해 확인을 거쳐 켤 수 있으며 삭제·설치·외부 전송도 자동 허가합니다. [키·권한 안내](https://github.com/MaoEmong/pixel-office/blob/main/docs/KEYS-AND-PERMISSIONS-KO.md)를 읽고 선택하세요.

## 업데이트와 문제 제보

업데이트 전에는 진행 중인 작업을 마치고 앱을 정상 종료한 뒤 다음 폴더를 백업합니다.

- 앱 설정·조직·키·프로젝트 기록: `%LOCALAPPDATA%\pixel-office`
- 프로젝트별 대화와 작업 기록: 각 프로젝트의 `.pixel-office`

새 ZIP은 이전 설치 폴더에 덮어쓰지 말고 **새 폴더**에 풉니다. 새 버전은 기존 데이터로 복구를 시도하지만, 로그인·권한 문제는 사용자의 조치가 필요할 수 있습니다. 이전 버전으로 돌아갈 때는 백업한 데이터도 복원해야 할 수 있습니다. 키 저장소 파일은 다른 Windows 계정이나 PC로 옮기면 열리지 않을 수 있습니다.

웹 미리보기에는 Microsoft Edge WebView2 Runtime이 필요하며 ZIP에 포함하지 않습니다. 원격 접속은 [별도 안내](https://github.com/MaoEmong/pixel-office/blob/main/docs/원격접속.md)를 참고하세요.

문제는 [GitHub 이슈](https://github.com/MaoEmong/pixel-office/issues)에 버전·사용 AI·오류 문구·재현 순서와 함께 제보하세요. 인증 파일, 키·비밀번호와 비공개 프로젝트 내용은 첨부하지 마세요. [처음 사용 안내](https://github.com/MaoEmong/pixel-office/blob/main/docs/FIRST-USE-KO.md)와 [검증 기록](https://github.com/MaoEmong/pixel-office/blob/main/docs/release/0.2.1/VERIFICATION.md)도 확인하세요.

## 0.2.0에서 업데이트할 때

진행 중인 검사·명령은 끝까지 두고, 후속 작업은 잠시 보류하도록 부장에게 안내하세요. 모든 담당자의 실행이 끝나고 질문·허가·작성 중 입력이 없는지 확인한 뒤 앱을 정상 종료합니다. 앱 데이터 폴더와 프로젝트의 `.pixel-office`를 함께 백업하고 새 ZIP을 별도 폴더에 풉니다. 같은 Windows 계정과 작업 폴더로 실행하면 기존 대화와 미완료 업무의 복구를 시도합니다. 복구 뒤 기록을 확인하고 부장에게 이어서 진행하도록 알려 주세요.

이번 버전은 긴 대화 기록을 새 저장 형식으로 한 번 변환하며, 변환 전에 강제 백업을 만듭니다. 변환된 데이터 폴더를 0.2.0 이하 앱으로 다시 열지 마세요. 정상 종료와 기록 복구가 실행 중 명령까지 끊김 없이 옮긴다는 뜻은 아닙니다.
