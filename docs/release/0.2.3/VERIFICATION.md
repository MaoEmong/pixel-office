# Windows 0.2.3 배포 검증

2026-10-28 기준입니다. 같은 Windows PC에서 기존 계정·진행 중인 사용자 작업과 분리한 환경으로 검사했습니다. 저장소의 GitHub 자동 검사 작업은 설정돼 있지 않으며, 아래 결과는 최종 소스와 실행 묶음의 로컬 검사 결과입니다.

## 소스 검사와 배포 전 검토

- 서버 전체 1,581 통과·17 제외·실패 0, 형식 검사 통과.
- PC 화면 전체 995 통과·1 제외·실패 0, 분석 검사 지적 없음. 별도 데이터 폴더와 메모리 화면 설정을 사용했습니다.
- 실제 접속 준비 전 공개·잘못된 포트 거절, 순간 읽기 잠금과 지속 잠금·기존 파일 보존·동시 갱신을 확인했습니다.
- 배포 전 독립 검토에서 접속 공개 실패 뒤 AI 정리 누락과 종료 뒤 접속 파일 재생성을 재현해 보완했습니다. 실제 제품 진입점이 쓰는 같은 함수로 복구한 가짜 AI 종료와 업무·대화·일시 닫힘 상태 보존을 확인했습니다. 관련 연결·종료·중복 실행 검사 56개 통과. 실제 AI나 사용자 작업을 실패 실험에 사용하지 않았습니다.
- 화면 전체 검사 첫 실행은 기존 사용자 설정을 읽어 기본 폭 기대값이 달랐고, 닫힌 상태에 늦은 설정 읽기가 접근해 실패했습니다. 지연 읽기·저장·화면 종료의 다섯 경우를 재현해 보완했고, 패널 검사도 실제 설정을 읽지 않도록 분리했습니다. 최종 전체 검사는 별도 데이터 폴더에서 통과했습니다.
- 복구 안내의 길이 제한·완전한 구조·비밀값 가림, 입력 접수 실패와 지연의 읽기 전용 진단, 부장·팀장 도구의 실제 활동과 접수 상태를 검사했습니다. 상태 조회가 작업 재전송·허가·완료를 대신하지 않습니다.
- 빌드 작업·임시 파일과 Node·Dart·npm·NuGet 캐시가 프로젝트 드라이브를 기본으로 사용하도록 보완하고, 사용자 C 경로와 다른 출력 드라이브·직접 지정한 캐시 경로를 대조했습니다. 공간이 부족한 드라이브에서는 빌드를 시작하지 않습니다.

## 최종 ZIP 검사

- 새 Windows 앱·서버를 별도 폴더에서 빌드하고 ZIP을 다시 풀어 목록의 1943개 실행 파일·구성품 해시와 실제 파일 목록을 대조했습니다. 원본 TypeScript·Dart·소스맵·인증 파일·사용자 데이터와 개발 도구를 제외했습니다.
- 실제 Windows 앱의 빈 사용자 경로·별도 데이터·포트에서 시작, 원격 화면, 미설치 AI 안내, 정상 종료, 설정 보존과 서버 자동 복구 10항목을 새 환경으로 두 번 모두 통과했습니다. 실제 AI를 호출하지 않는 검사입니다.
- 구형 형식의 대화 5,000개를 강제 백업 뒤 변환하고 전체 페이지·변경분 전달·두 번 시작 후 보존을 확인했습니다.
- 포장된 서버의 실제 종료 hook으로 미완료 업무·추가 배정·결과 대기 관계가 유지되는지 확인했습니다.
- 포장된 서버의 문서 읽기·편집·충돌/경로 보호, 파일 저장·확인 후 복구·타임라인 보존, Windows 암호화 키 보관과 확인 없는 전체 허가 거절을 검사했습니다. 키 등록 전 저장한 대화도 등록 뒤 조회에서 가려지며 두 번 시작 후 보존됐습니다.
- 실제 Windows 출력 연결 회귀 검사 4개 통과. 배포 파일과 공개 문서에서 검사 대상으로 둔 개인 식별 문자열은 발견되지 않았습니다. 모든 개인정보나 비밀값의 부재를 보증하는 검사는 아닙니다.

## 적용 확인과 최종 배포본의 구분

연결 준비·지시 전달 상태 수정을 포함한 선행 로컬 실행본을 실제 작업에 적용하면서 AI 대화 7개, 업무 167건, 대화/첨부 348개, 질문/허가 78건과 완료 단계 5건의 보존을 확인했습니다. 새 업무의 실제 접수·결과 저장·완료 보고·상사의 후속 응답과 후속 검사 시작도 확인했습니다.

이번 배포 전 추가한 시작 실패 정리·화면 설정 종료 보완은 위의 별도 환경에서 검사했습니다. 최종 0.2.3 ZIP을 만들기 위해 진행 중인 사용자 작업을 종료하거나 앱을 다시 교체하지 않았습니다. 로컬 작업 확인과 최종 ZIP 검사, 사용자 프로젝트 전체 완료는 서로 다릅니다.
