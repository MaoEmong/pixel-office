# 저장된 키와 모든 권한 허용

## 키 저장소

상단 메뉴의 **키 저장소**에서 현재 프로젝트가 사용할 API 키, 로그인 아이디, 비밀번호를 이름과 값으로 저장합니다. 이름은 `GITHUB_TOKEN`, `LOGIN_ID`, `LOGIN_PASSWORD`처럼 적고, 설명에는 어디에 쓰는 정보인지 적습니다.

저장한 항목은 해당 프로젝트의 부장·팀장·팀원이 `secret_list`로 이름과 설명을 확인하고 `secret_get`으로 조회할 수 있습니다. 다른 프로젝트의 항목은 이 도구로 조회할 수 없습니다. 값이 있다는 사실만으로 원래 지시 범위 밖의 작업이 허용되는 것은 아닙니다.

값은 Windows 계정에 연결된 암호화 방식으로 앱 데이터 폴더의 `secrets.vault`에 저장합니다. 평문으로 저장하는 대체 방식은 없습니다. 현재 Windows에서 지원하며, 다른 환경에서는 저장 버튼이 비활성화됩니다. 다른 PC나 Windows 계정으로 파일만 옮기면 열지 못할 수 있으므로 필요한 값을 다시 입력해야 합니다. 파일이 손상되거나 열리지 않아도 기존 파일을 덮어쓰지 않습니다.

목록에서는 값을 표시하지 않으며 수정 화면에서만 숨겨진 값으로 불러옵니다. 앱의 작업 기록·오류 설명·서버 로그에서는 등록된 원문 값을 가리고, 타임라인에는 키 이름과 조회자를 기록합니다. 등록된 값이 들어 있는 파일은 새 파일 저장 지점에서 제외합니다.

한도 중지 후 복구를 위해 보관하는 대기 입력에서도 등록된 값을 가립니다. 앱을 다시 연 뒤 해당 값이 필요하면 AI가 키 저장소에서 다시 조회하거나 사용자에게 재확인을 요청할 수 있습니다.

**값을 AI에 넘기면 해당 AI 서비스와 CLI 자체 대화·터미널 기록에 포함될 수 있습니다.** 앱의 가림 처리는 이 외부 기록을 지우거나 모든 형태의 노출을 차단하는 기능이 아닙니다. AI가 값을 출력·소스·Git에 복사하지 않도록 안내하지만, AI에게 공개한 값을 다시 회수할 수는 없습니다. 키 삭제는 앞으로의 앱 조회를 막으며 외부 서비스의 키 자체를 폐기하지 않습니다.

저장된 아이디·비밀번호가 있어도 로그인 인증번호, 추가 본인 확인, 운영체제의 확인창까지 자동 처리하지는 않습니다.

## 모든 권한 허용

상단 메뉴의 **허가 방식 → 모든 권한 허용**에서 경고 내용을 읽고 이해 확인에 체크한 뒤 확인 버튼을 눌러 선택합니다. 기존 프로젝트의 방식 변경은 이어서 **바꾸기**를 눌러 저장합니다. 새 프로젝트를 만들 때도 같은 확인을 거칩니다. 앱은 확인 표시 없이 이 방식으로 전환하는 요청을 거절합니다.

이 설정은 해당 프로젝트의 부장·팀장·팀원이 앱에 보내는 허가 요청을 자동으로 허용합니다. 파일 삭제·프로그램 설치·명령 실행·온라인 전송·작업 폴더 밖 접근도 포함합니다. 자동 허가 이유는 기록에 남고, 설정이 켜져 있는 동안 상단에 표시합니다. 기본값은 **전부 묻기**이며 언제든 다시 바꿀 수 있습니다. 이미 대기 중인 요청에 소급 적용하지 않습니다.

잘못된 실행으로 파일이 없어지거나 저장한 인증 정보가 외부로 전달될 수 있습니다. 파일 되돌리기는 온라인 전송이나 외부 서비스의 변경까지 되돌리지 않습니다. 로그인·운영체제 확인창·AI 프로그램 자체의 제한과 앱 내부 직급 규칙은 별개입니다.

키 저장과 허가 방식 변경만으로 프로젝트의 Git 커밋이나 원격 저장소 전송이 실행되지는 않습니다.
