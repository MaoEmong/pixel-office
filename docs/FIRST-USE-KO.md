# 픽셀 오피스 처음 사용하기

픽셀 오피스는 여러 AI가 맡은 일과 대화, 사용자의 허가를 기다리는 요청을 사무실 화면에서 확인하는 윈도우 앱입니다. **처음에는 AI 하나와 작은 작업으로 시작하세요.**

## 1. 사용할 AI 하나 준비하기

아래 프로그램 중 사용할 것만 공식 안내에 따라 설치하고 로그인하세요.

- [Claude Code 설치 안내](https://code.claude.com/docs/en/setup)
- [Codex 설치 안내](https://developers.openai.com/codex/cli/)
- [Antigravity 설치 안내](https://antigravity.google/docs/cli/)

AI 계정과 이용 가능한 요금제·사용량은 각 서비스의 조건을 따릅니다. 픽셀 오피스가 AI 이용권을 제공하지는 않습니다.

픽셀 오피스 첫 화면의 **준비 상태 확인**을 누르세요. 기존 사용자는 오른쪽 위 **⋮ → 환경 점검 · CLI 로그인**에서도 열 수 있습니다. 사용할 AI의 설치와 로그인이 확인되면 다음으로 넘어가세요. 새로 설치한 AI를 찾지 못하면 앱을 다시 열어보세요.

## 2. 부서 만들기

1. **부서 만들기**를 누릅니다.
2. 연습용 폴더나 기존 프로젝트의 복사본을 고릅니다.
3. **이 부서에서 사용할 AI**를 체크합니다. 여러 개를 선택할 수 있으며, 선택한 AI를 부장·팀장·팀원이 사용합니다.
4. 체크한 AI 중 **부장으로 사용할 AI**를 고릅니다. 부장은 목표를 정리하고 팀을 구성하는 AI입니다.
5. 처음에는 허가 방식을 기본값인 **전부 묻기**로 유지합니다.
6. 부서를 만듭니다. AI가 폴더 접근을 확인하면 표시된 경로를 보고 허가 여부를 결정하세요.

AI 선택은 이 부서에만 적용됩니다. 나중에 상단의 **AI 설정 변경**에서 해당 부서의 사용 AI를 바꿀 수 있습니다.

만든 부서는 왼쪽 목록에서 선택합니다. 목록은 위아래로 스크롤할 수 있고, 부서가 많으면 이름으로 찾을 수 있습니다. 화살표나 상단의 목록 버튼으로 접고 펼칠 수 있습니다. 상단에는 현재 선택한 부서 이름만 표시합니다.

## 3. 첫 지시 보내기

화면 아래 부장 입력칸에 다음 문장을 복사해 보내보세요.

> 이 폴더의 프로젝트를 살펴보고 구조와 실행 방법을 설명해줘. 파일은 아직 수정하지 말고, 다음에 할 일을 제안해줘.

AI가 실제로 답하는지 확인한 뒤 작은 수정 작업을 맡겨보세요. 한 번에 많은 팀원을 쓰면 AI 사용량도 늘어날 수 있습니다.

## 4. 진행 상황과 허가 요청 확인하기

- 캐릭터를 누르면 해당 AI의 대화와 작업 기록을 확인할 수 있습니다.
- **내 책상**에는 사용자의 허가나 답변이 필요한 요청이 모입니다. 작업 설명과 영향을 읽고 결정하세요.
- 오류가 나오거나 답변이 멈춘 것 같으면 오류 안내와 해당 멤버의 터미널을 확인하세요. 같은 요청을 반복해서 보내기 전에 이미 실행됐는지 살펴보세요.

**진행·기록**에서는 요청 하나를 펼쳐 관련 AI 작업과 파일 저장 지점을 함께 볼 수 있습니다. 완료 보고를 받으면 **완료 결과** 카드에 보고 내용, 저장 시점 사이에 바뀐 파일, 보고된 검사 결과가 모입니다. 검사 실행 기록만 있고 결과 보고가 없으면 통과 여부를 표시하지 않습니다. 이전 버전의 기록 중 요청 연결 정보가 없는 항목은 개별 기록으로 남습니다.

완료 카드의 **결과 화면 보기**는 이 부서에 등록한 웹 미리보기를 엽니다. 주소가 없으면 등록 화면으로 이동합니다. 현재 실행 중인 웹 화면이며 완료 당시의 화면 사진을 보관하는 기능은 아닙니다.

실행 허가·답변 대기, 입력 접수 실패는 앱의 **확인 대기** 알림에 표시됩니다. 입력을 전달 중인 상태가 2분 넘게 이어져도 확인을 안내합니다. 다른 부서의 대기도 모아 보여주며 **확인하기**로 해당 화면에 이동할 수 있습니다. 새 항목이 생기면 앱 안내와 알림 소리를 내고, 해결되지 않으면 5분 뒤 한 번 더 알립니다. 스피커 버튼으로 소리를 끌 수 있습니다. 알림은 앱이 실행 중일 때 동작하며 Windows 알림 센터에 따로 등록되지는 않습니다. AI끼리의 답변·작업 순서 대기는 사용자 알림 대상에서 제외합니다.

이 안내는 앱 오른쪽 위 **⋮ → 처음 사용 안내**에서 다시 볼 수 있습니다.

### 진행 보고와 답변 대기 구분

팀장·팀원은 중간 진행 상황을 알리면서 작업을 계속할 수 있습니다. 이 보고는 질문이나 완료 보고로 처리하지 않습니다. 실제로 상사의 판단이 필요한 질문만 답변 대기로 남습니다. 작업을 계속하는 AI에게 미응답 질문도 있으면 **작업 중 · 상사에게 미응답 질문 N개**처럼 함께 표시합니다.

부장은 질문이 남은 팀장에게 새 업무를 쌓기 전에 해당 질문에 먼저 답해야 합니다. 질문이 여러 개면 답할 질문을 지정하므로 다른 질문이 잘못 닫히지 않습니다. 기존에 남아 있는 질문은 임의로 지우거나 자동으로 답하지 않습니다.

### Docker 때문에 작업이 멈췄을 때

Docker 실행 문제로 중단됐다는 보고가 오면 큰 오류 팝업 대신 **Docker 실행 대기 카드**가 표시됩니다. **Docker 실행**은 설치된 Docker Desktop에 실행 요청만 보내며, 실제 준비 여부는 **다시 확인**으로 검사합니다. 서버 응답이 확인돼야 **작업 이어가기**를 누를 수 있습니다. 재개할 때는 기존 계획과 완료 기록을 유지하고 중단 보고된 업무의 미완료 항목을 다시 요청합니다. 프로젝트의 모든 오류가 해결됐다는 의미는 아닙니다.

**원인·해결 안내**에서는 확인된 상태와 최근 오류 기록을 보고 복사할 수 있습니다. 기록은 이전 실행에서 나온 것일 수 있어 확인 시각을 함께 표시합니다. Docker 자체가 시작에 실패하거나 PC 설정 변경이 필요한 경우에는 사용자가 해당 안내를 따라야 합니다. 앱은 설치·재설치·데이터 초기화·관리자 권한 변경을 자동으로 하지 않습니다. Docker 직접 실행은 Windows와 macOS에서 지원하며, 다른 환경에서는 Docker를 직접 실행한 뒤 다시 확인하세요.

### AI 사용 한도를 모두 썼을 때

AI가 사용 한도 소진을 알리거나 사용량 조회에서 소진이 확인되면 해당 부서의 실행을 멈추고 안내 창을 표시합니다. 기존 업무·질문·대화 기록·완료 단계와 이미 바뀐 파일은 보존합니다.

앱에서 사용하도록 선택한 AI 중 구독 로그인과 남은 사용량이 확인된 다른 AI가 있으면 교체 여부를 묻습니다. **교체하고 계속**을 눌러야 담당 AI를 바꾸고 작업을 이어갑니다. **교체 안 함·작업 중지**를 선택하거나 확인된 후보가 없으면 중지 상태를 유지합니다. 확인되지 않은 AI를 사용 가능하다고 가정하거나 API 키 방식으로 자동 전환하지 않습니다.

AI가 바뀌면 이름·담당 역할·업무 번호와 진행 단계는 유지합니다. 기존 대화 기록은 남고 새 AI에는 진행 요약, 질문·답변과 미완료 업무를 전달합니다. 중지 직전 실행하던 명령은 결과를 확인한 뒤 이어가므로 일부 작업을 다시 검사할 수 있습니다.

중지 후에는 화면 아래의 **AI 선택·다시 확인**에서 재개 방법을 다시 볼 수 있습니다. **다시 확인·기존 AI 재개**를 누르면 사용량을 새로 조회하고, 기존 구성의 AI가 모두 사용 가능할 때 같은 AI·대화로 이어갑니다. 일부만 회복됐으면 아직 확인이 필요한 AI 이름을 표시하고 중지를 유지합니다. **원래 AI로 계속**도 기존 구성을 유지하며 다른 담당자의 AI를 바꾸지 않습니다. 앱이나 안내 창을 여는 것만으로는 재개하지 않습니다.

AI 선택 목록에는 현재 항목의 체크와 **선택됨** 표시가 있습니다. 목록에서 AI를 고르는 것만으로는 재개하거나 교체하지 않습니다.

팀장이나 팀원을 새로 만들 때도 한도 소진이 확인된 AI는 피합니다. 부서와 팀에서 허용한 다른 구독 AI 중 연결과 최근 남은 사용량을 확인한 후보가 있으면, 가장 여유가 큰 AI로 생성하고 변경 내용을 알림과 진행 기록에 남깁니다. 후보가 없으면 하위 AI를 만들지 않고 이유를 안내합니다. 기존에 일하던 AI의 종류나 업무는 이 선택으로 변경하지 않습니다.

지정한 AI가 아직 사용량을 제공하지 않았다는 이유만으로 한도 소진이라고 판단하지는 않습니다. 다만 소진된 AI 대신 자동으로 선택할 후보는 구독 로그인과 남은 사용량이 확인되어야 합니다. 생성 안내에서 멈춘 경우 AI 설정·사용량을 확인한 뒤 부장에게 다시 요청하세요.

### 연결이 오래 복구되지 않는 AI를 강제 퇴근시키기

사용 한도 소진으로 이미 중지한 부서는 AI 실행이 종료된 상태입니다. 이 경우에는 퇴근 대신 아래 **AI 선택·다시 확인**에서 재개하거나 다른 AI로 교체하세요.

멈춘 AI를 선택하면 오른쪽 **AI 상세**의 상태 옆에 **강제 퇴근** 버튼이 표시됩니다. 버튼을 누르면 함께 퇴근할 AI와 중단할 업무·허가 대기 수를 먼저 보여줍니다. 내용을 확인하고 **강제 퇴근**을 눌러야 실제 종료합니다. 취소하면 종료하지 않습니다.

팀장을 종료하면 그 아래 팀원도 함께 퇴근하며, 부장을 종료하면 해당 부서의 하위 AI도 모두 퇴근합니다. 대화와 작업 기록은 남고 이미 바뀐 파일을 이전 상태로 되돌리지는 않습니다. 저장되지 않은 응답과 실행 중이던 명령의 결과는 확인이 필요할 수 있습니다.

부장에게도 같은 부서의 하위 AI를 강제 퇴근시킬 수 있는 기능이 있습니다. 예를 들어 “연결이 복구되지 않는 프론트엔드팀장을 강제 퇴근시키고, 후임을 구성해 미완료 작업을 이어가 줘”라고 지시할 수 있습니다. 사용자 버튼은 종료까지만 처리하므로, 후임 구성은 부장에게 요청하세요. 부장이 퇴근했다면 부장을 다시 고용한 뒤 요청할 수 있습니다.

## 5. 프로젝트 문서 읽고 수정하기

부서를 선택한 뒤 오른쪽의 **파일·문서**를 누르세요. 폴더를 펼치면 해당 프로젝트의 파일 구조를 볼 수 있습니다. 문서를 누르면 열리고, **보기 / 편집**으로 전환해 내용을 확인하거나 고친 뒤 **저장**할 수 있습니다. 문서가 좁게 보이면 **문서 넓게 보기** 버튼을 누르세요.

현재는 UTF-8로 저장된 `.md`, `.markdown`, `.txt` 문서 중 2MB 이하인 파일을 지원합니다. 목록은 펼친 폴더만 읽으며, 파일이 많은 폴더는 **파일 더 보기**로 이어서 불러옵니다. 기본 목록에서 빠진 자동 생성 폴더는 목록 위의 표시 설정에서 볼 수 있습니다. 다른 위치로 연결된 파일·폴더와 앱 내부 기록 폴더는 이 화면에서 열지 않습니다.

AI나 다른 프로그램이 같은 문서를 바꾸면 작성 중인 글을 유지하고 저장을 막습니다. **최신 내용 비교**에서 두 내용을 확인하고, 필요하면 내가 쓴 글을 복사한 뒤 **최신 내용으로 다시 열기**로 현재 파일을 불러오세요. 확인 없이 다른 사람이나 AI의 변경을 덮어쓰는 버튼은 제공하지 않습니다.

저장 전의 글은 탭이나 부서를 옮겨도 앱 안에 남아 있습니다. 앱을 완전히 닫으면 없어지므로 종료 전에 저장하세요. 저장하지 않은 문서가 있으면 앱을 닫을 때 안내합니다.
